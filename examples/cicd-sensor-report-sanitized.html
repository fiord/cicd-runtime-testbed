cicd-sensor HTML report（サニタイズ済みの形式例）

これは実測 report の構造を説明するためのサンプルです。actor、commit、runner ID、 完全な argv、path、接続先は意図的に伏せています。生 report を repository に 恒久保存してはいけません。

ルール hit の例

実際の report は rule ごとに、event 種別、process、payload、判定 action を保持します。

ruleeventprocess / payload の例action
testbed_canary_argv_carrier process_exec /usr/bin/curl --referer CNRY…
ancestors: bash → Runner.Worker		 collect
testbed_canary_path_probe file_open path: /tmp/CNRY…/marker
read/write フラグ、実行 process		 detect
testbed_canary_http_host http_request host、method、source process（実値は伏せる） collect

この形式から分かること

  • 検知結果は「何の rule が、どの event に一致したか」を調査できる。
  • 同時に argv、path、ネットワーク先、CI/CD メタデータを含み得る。
  • したがって artifact はログではなく、アクセス制御すべき調査データである。
